# 고객관리 CRM 설계 문서

- 작성일: 2026-08-20
- 대상: 1인 사용 웹 CRM (Next.js + Supabase + Vercel)

## 1. 목적 및 범위

혼자 사용하는 고객관리(CRM) 웹 서비스를 구축한다. 고객을 개별로 등록하거나
엑셀 양식으로 일괄 등록할 수 있고, 목록 화면에서 필드별 정렬과 구분(유입 경로)
기준 체크박스 필터를 제공한다. GitHub 저장소에 연결해 Vercel에 배포하여
운영한다.

## 2. 사용자 및 인증

- 단일 사용자 전제. 별도 회원가입/로그인 시스템은 두지 않는다.
- 다만 배포된 URL에 누구나 접근 가능한 문제를 막기 위해, 환경변수
  (`SITE_PASSWORD`)로 지정한 비밀번호를 입력해야 통과되는 미들웨어 기반
  게이트를 둔다. 통과 시 쿠키를 발급해 이후 요청은 자동 통과시킨다.

## 3. 전체 아키텍처

```
[브라우저]
   │ 폼 제출 / 엑셀 업로드 / 정렬·필터 클릭
   ▼
[Next.js App Router] (Vercel 배포, GitHub 연동 자동 배포)
   │ Server Actions ("use server")
   │  - createCustomer(input)
   │  - bulkImportCustomers(rows)
   │  - updateCustomer(id, input)
   │  - deleteCustomer(id)
   │  - getCustomers()
   ▼
[Supabase (PostgreSQL)]
   customers 테이블, source_options 테이블
```

- 비즈니스 로직(유효성 검사, 중복 체크, 엑셀 파싱 검증)은 전부 서버
  (Server Action)에서 수행한다. 브라우저에는 결과만 전달해 개인정보(연락처,
  이메일) 처리 로직이 클라이언트에 노출되지 않도록 한다.
- 정렬/필터는 전체 데이터를 한 번에 가져온 뒤 클라이언트에서 즉시
  정렬·필터링한다 (개인 CRM 규모를 고려해 페이지 새로고침 없이 즉각 반응하는
  방식을 택함). 데이터가 수만 건 이상으로 커지면 서버 사이드 페이지네이션으로
  전환이 필요하다.
- GitHub main 브랜치에 push하면 Vercel이 자동으로 빌드·배포한다.

## 4. 데이터 모델

### customers 테이블

| 컬럼 | 타입 | 필수 | 설명 |
|---|---|---|---|
| id | uuid (PK, default gen_random_uuid()) | - | 기본키 |
| source | text (CHECK: source_options.value 중 하나) | ✅ | 구분(유입 경로) |
| name | text | ✅ | 이름 |
| company | text | ✅ | 소속(회사) |
| phone | text | ✅ | 연락처 (원문 그대로 저장, 화면 표시용) |
| phone_normalized | text | ✅ (자동 생성) | 연락처에서 숫자만 추출한 값. 중복 체크·정렬 보조용 |
| email | text | - | 이메일 |
| memo | text | - | 메모 |
| created_at | timestamptz (default now()) | - | 등록일시 |
| updated_at | timestamptz (default now(), on update) | - | 수정일시 |

### source_options 테이블

| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | uuid (PK) | 기본키 |
| value | text (unique) | 구분 값 (예: "지인소개") |
| sort_order | int | 드롭다운/체크박스 노출 순서 |

기본 시드 데이터: 지인소개, 웹사이트, 광고, 전시회·박람회, 콜드콜, 기존고객 소개, 기타.
화면(설정 메뉴 또는 목록 화면 내)에서 추가/수정/삭제가 가능하도록 관리 UI를
제공한다.

### 연락처 정규화 규칙

저장 시 `phone`에서 숫자만 추출해 `phone_normalized`에 함께 저장한다
(예: `010-1234-5678` → `01012345678`). 중복 검사와 검색은
`phone_normalized` 기준으로 수행하고, 화면에는 사용자가 입력한 원래 형식
(`phone`)을 그대로 보여준다.

## 5. 화면 및 기능

### 5.1 고객 목록 (메인 화면)

- 테이블 컬럼: 구분 / 이름 / 소속 / 연락처 / 이메일 / 메모 / 등록일
- 컬럼 헤더 클릭 시 해당 필드 기준 오름차순/내림차순 토글 정렬 (모든 컬럼 지원)
- 상단 체크박스 필터: `source_options` 값들을 체크박스로 나열, 체크된
  구분만 표시 (다중 선택 가능, 전체 해제 시 전체 표시)
- 통합 검색창: 이름/소속/연락처/이메일 대상 실시간 텍스트 검색
  (검색어와 체크박스 필터는 AND 조건으로 결합)
- 행 클릭 또는 행 내 버튼으로 수정/삭제 가능
- "양식 다운로드", "엑셀 일괄등록", "엑셀 내보내기" 버튼 배치

### 5.2 개별 등록

- 입력 폼: 구분(드롭다운, 필수) / 이름(필수) / 소속(필수) / 연락처(필수) /
  이메일 / 메모
- 필수값 누락 시 인라인 에러를 표시하고 저장을 막는다.
- 저장 시도 시 `phone_normalized` 기준 기존 고객과 중복이면, 기존 고객 정보
  (이름/소속/등록일)를 보여주며 "그래도 등록" 여부를 확인받는다.

### 5.3 엑셀 일괄 등록

1. "양식 다운로드": 헤더(구분/이름/소속/연락처/이메일/메모)와 예시 1행이
   채워진 `.xlsx` 파일을 제공. 구분 컬럼 예시값은 `source_options` 목록과
   동일하게 안내한다.
2. 사용자가 양식을 채워 업로드하면 서버(Server Action)에서 파싱해 행 단위로
   검증한다:
   - 필수값(구분/이름/소속/연락처) 누락 → 오류로 표시
   - 구분 값이 `source_options`에 없는 값 → 오류로 표시
   - `phone_normalized` 기준 기존 고객 또는 업로드 파일 내부와 중복 →
     건너뛰고 알림 대상으로 표시
3. 미리보기 화면에 "정상 N건 / 중복 제외 N건 / 오류 N건(사유)"을 보여주고,
   사용자가 확인 후 "등록" 버튼을 눌러야 정상 행만 일괄 저장된다.

### 5.4 엑셀 내보내기

- 현재 목록 화면에 적용된 필터/검색 상태 그대로를 기준으로 `.xlsx` 파일을
  생성해 다운로드한다. 백업 및 외부 보고 용도.

## 6. 에러 처리

- 폼/엑셀 업로드 공통으로 검증 실패 시 한글 오류 메시지를 필드별/행별로
  명확히 표시한다.
- 엑셀 일괄 등록은 부분 실패를 허용한다: 정상 행만 저장하고 오류/중복 행은
  사유와 함께 반려한다 (전체 롤백 방식은 사용하지 않음 — 다수 행 중 일부
  오류로 전체가 실패하면 사용자 경험이 나빠지기 때문).
- 서버/네트워크 오류 시 토스트로 알리고, 입력 중이던 폼 데이터는 유지해
  재입력 부담을 줄인다.

## 7. 기술 스택 요약

- Next.js (App Router), Server Actions
- Supabase (PostgreSQL) — DB만 사용, Supabase Auth는 사용하지 않음
  (비밀번호 게이트는 자체 미들웨어로 구현)
- 엑셀 파싱/생성: `xlsx` (SheetJS) 라이브러리
- 배포: GitHub 저장소 → Vercel 연동 자동 배포

## 8. 범위 밖 (Out of Scope)

- 다중 사용자 로그인/권한 관리
- 고객 상담 이력, 파이프라인(영업 단계) 관리 등 CRM 고급 기능
- 서버 사이드 페이지네이션 (데이터가 대규모로 늘어나면 추후 별도 설계 필요)
